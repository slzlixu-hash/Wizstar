## 踩坑记录（重要）

1. **HTTP_PROXY 再现**：本机环境 HTTP_PROXY=127.0.0.1:55109 会把 127.0.0.1 的 POST /mcp 转成绝对地址，Node 端 req.url 失配返回 404（URL 看起来全对但就是 404 时先查代理）。已用 `LoopbackBypassProxy`（IWebProxy，回环 GetProxy 返回 null）挂在 "mcp"/"llm" 命名客户端上解决——比旧项目方案更轻。
2. **JSON-RPC result 包裹**：MCP 响应的 serverInfo/tools/content 都在 `result` 内，客户端必须先取 result 再取字段。
3. **FI 客户端步数上限不抛异常**：FunctionInvokingChatClient 到 MaximumIterationsPerRequest 后返回空文本而非抛错；步数预算必须自己在 AIFunction 包装层实现（超预算返回结构化提示促模型收敛，status 判 max_steps）。
4. **RiskClassifier 陷阱**：未声明 x-risk 时不能按 write 兜底参与「只升不降」合并（否则盖掉动词推断的 read）；只有显式声明才参与合并。
5. **Minimal API DI**：端点 lambda 参数类型必须在容器中注册，否则被推断为 Body 参数导致启动失败（McpToolProvider 需同时注册具体类型与 IToolProvider 转发）。
6. 测试中 raw string literal 追加 YAML 时注意首行换行（否则拼到上一行的 plain scalar 里报 invalid mapping）。
